2.2 다중 물류창고 / WMS 연동 대응 작업

인도 시장 특성상 다수의 물류창고(멀티 로케이션) 운영이 일반적이며, 창고별 사용 언어·시스템·운영 방식이 상이합니다. 'OMS + 수기 WMS 업로드' 방식은 다음과 같은 구조적 이슈로 현실적 운영이 어렵습니다.

다중 WMS 자동 연동을 위한 추가 작업
  • 멀티 WMS 통합 허브 구조 — N개 WMS 동시 연동 가능한 Hub & Spoke 아키텍처 설계
  • 창고별 어댑터 레이어 — 각 WMS 전용 어댑터 모듈 신규 개발
  • 재고 동기화 정책 — 실시간 재고 통합 뷰 + 창고 간 재고 이동 트랜잭션 처리
  • 주문 라우팅 로직 — 출고 우선순위 룰 엔진 (재고/지역/SLA 기반)
자동 연동 불가 창고에 대한 수기 운영 대응
  • 표준 업로드 템플릿 — 창고별 언어/포맷 맞춤 출고 지시서 자동 생성
  • 수기 업로드 검증 모듈 — SKU/수량/상태 자동 검증 + 오입력 즉시 경고
  • 재고 차이 리포트 — OMS vs 수기 보고 재고 차이 자동 감지 + 일일 리포트
  • 수기 운영 대시보드 — 처리 현황 실시간 가시화 + SLA 지연 사전 감지
  • 단계적 전환 지원 — 수기 → 부분 자동 → 완전 자동 하이브리드 모드

※ 위 작업은 인도 시장의 멀티 창고/언어 특성에 대응하기 위한 BMF만의 추가 투자 영역으로, Eshopbox 단일 창고 연동만으로는 해결되지 않는 영역입니다.

2.3 기술적으로 더 고도화된 / Specialized 작업

본 Custom 연동은 단순한 'Eshopbox API 호출 코드 작성'이 아닌, Eshopbox 자체 시스템보다 더 높은 수준의 통합 엔지니어링 작업을 요구합니다. BMF가 단순 클라이언트가 아닌, 다중 시스템을 조율하는 통합 허브 역할을 수행하기 때문입니다.

영역 Eshopbox 자체 작업 수준 BMF가 수행해야 하는 Specialized 작업
API 통신 단일 클라이언트 ↔ Eshopbox 간 표준 호출 다중 외부 시스템(b.stage, OMS, 결제, 멤버십, 다중 WMS)을 조율하는 오케스트레이션 레이어 신규 설계
상태 관리 Eshopbox 내부 상태 코드 단일 운용 Shopify 표준 ↔ Eshopbox ↔ b.stage 3개 시스템 간 상태 매핑 및 일관성 보장 로직
데이터 정합성 Eshopbox 단일 DB 기준 분산 시스템 간 트랜잭션 정합성 (Eventual Consistency, 보상 트랜잭션, 멱등성 보장) 신규 구현
이벤트 처리 Eshopbox Webhook 단방향 발신 Webhook 수신 + 재시도 + 중복 제거 + 순서 보장 + Dead Letter Queue 등 메시지 신뢰성 보장
SKU / 상품 모델 실물 상품 중심 단일 모델 디지털 굿즈 / 실물 / 멤버십 / 번들 / 한정판 등 b.stage 고유 상품 유형을 매핑하는 상품 유형 추상화 계층
장애 대응 Eshopbox 장애 = 자체 시스템 복구 Eshopbox 장애 시 OMS 단독 운영 모드 / 큐잉 후 재전송 / Fallback 정책 등 비즈니스 연속성 로직
확장성 Eshopbox 단일 도메인 향후 타 물류사·타 국가·타 브랜드 onboarding 가능한 멀티-테넌시 / 어댑터 패턴 설계
모니터링 Eshopbox 자체 모니터링 End-to-End 트랜잭션 추적 (주문 발생 → 결제 → OMS → WMS → 배송 완료) + 실시간 알림 체계
!요약

Eshopbox는 자사 도메인 내의 단일 시스템 운영이 본질이지만, BMF OMS는 여러 이질적 시스템을 잇는 중앙 허브이므로 본질적으로 더 높은 수준의 분산 시스템 엔지니어링 역량이 요구됩니다. 이는 단순한 API 어댑터 개발이 아닌, Specialized Integration Architecture 영역에 해당합니다.

※ 정확한 일정은 Custom 연동 범위 확정 후 별도 산정이 필요하며, 본 보고서의 수치는 잠정치입니다.
