01 요약 (Executive Summary)

전반적 보안 위생: 양호 — Critical/High 미발견

FLO ZIP QA 빌드를 디컴파일하여 OWASP MASVS/MASTG 및 Mobile Top 10 기준으로 정적 점검했습니다. 치명적(Critical)·높음(High) 등급 취약점은 발견되지 않았습니다. 가장 중점적으로 본 중요정보 하드코딩 항목에서 실제 유출 시크릿은 확인되지 않았습니다.

핵심 관찰: 키 값은 자바·리소스 평문이 아니라 네이티브 라이브러리(libkeys.so)에서 런타임에 제공되며, 평문 노출이 없습니다. 암호화는 AES/GCM/NoPadding(권장 인증 암호화)만 사용되고 ECB·DES·RC4·MD5·SHA-1 같은 취약 원시함수는 발견되지 않았습니다. 노출 컴포넌트는 런처 액티비티와 권한 보호된 리시버로 제한되며, ContentProvider는 모두 비공개입니다.

개선이 권고되는 항목은 모두 중간~정보 등급의 하드닝(hardening) 성격입니다: 강한 난독화로 인해 정적 분석만으로 확인이 어려운 WebView JavaScript 브리지(수동 검증 필요), 백업 허용 설정, 서버 측 키 제한 확인 권고, 딥링크 입력 검증입니다.

03 상세 발견 항목

F-1 WebView JavaScript 브리지 노출 Medium

MASVS-PLATFORM · CWE-749 (Exposed Dangerous Method) · 위치: WebView 래퍼 클래스(R8 난독화)

증거
androguard 교차참조 분석 결과, WebView.addJavascriptInterface, WebSettings.setJavaScriptEnabled, setAllowFileAccess 호출이 각각 확인되었습니다. 
// androguard xref (호출처는 R8 난독화로 단축 클래스명)
WebView.addJavascriptInterface     → callers: 1
WebSettings.setJavaScriptEnabled   → callers: 1
WebSettings.setAllowFileAccess     → callers: 1
영향
JS 브리지가 신뢰할 수 없는(외부) 콘텐츠를 로드하는 WebView에 부착될 경우, 웹 콘텐츠에서 노출된 자바 메서드를 호출해 앱 권한으로 동작을 수행할 수 있습니다. 파일 접근이 함께 허용되면 로컬 파일 노출 위험도 더해집니다.
참고
강한 난독화로 인해 정적 분석만으로 브리지가 신뢰 콘텐츠 전용인지 확정할 수 없어 수동 검증 항목으로 분류했습니다. 호출처가 1건씩으로 제한적인 점은 자체 래퍼일 가능성을 시사합니다.
권고
브리지는 1차 당사자 HTTPS 콘텐츠에만 부착하고, 노출 메서드는 @JavascriptInterface로 명시적으로 한정하십시오. 불필요하면 setAllowFileAccess(false)·setAllowUniversalAccessFromFileURLs(false)로 설정하고, 딥링크 등 외부 입력 URL은 로드 전 호스트/스킴을 화이트리스트로 검증하십시오.

F-2 allowBackup 활성화 Low

MASVS-STORAGE · CWE-530 (Exposure via Backup) · 위치: AndroidManifest <application>

증거
<application … android:allowBackup="true" … >
영향
백업이 허용되면 디버그 가능/루팅 단말 등에서 adb backup 또는 백업 메커니즘을 통해 앱의 로컬 데이터(SharedPreferences, DB 등)가 추출될 수 있습니다. minSdk 28에서는 플랫폼 제약이 있어 위험이 제한적이라 Low로 평가했습니다.
권고
민감 데이터를 다루는 경우 android:allowBackup="false"로 설정하거나, dataExtractionRules(API 31+)·fullBackupContent로 민감 파일을 백업 대상에서 제외하십시오.

F-3 Google/Firebase API 키 리소스 내 포함 Low

MASVS-STORAGE · CWE-798 · 위치: res/values/strings.xml

증거
<string name="google_api_key">AIzaSy…REDACTED…AsnE</string>
<string name="google_crash_reporting_api_key">AIzaSy…REDACTED…AsnE</string>
영향
Firebase 연동에서 이 키가 리소스에 포함되는 것은 정상이며, 구글 문서상 이 값은 비밀이 아니라 식별자입니다. 다만 서버 측 제한이 없으면 할당량 도용 등 오남용이 가능합니다. 따라서 취약점이라기보다 설정 확인 권고 항목입니다.
권고
Google Cloud Console에서 해당 키에 애플리케이션 제한(Android 앱: 패키지명 + 서명 SHA-1)과 API 제한(필요한 Firebase API로 한정)이 적용되어 있는지 확인하십시오. 결제형 API(Maps/Places 등)에 접근 가능한 무제한 키라면 등급이 상향됩니다.

F-4 노출 액티비티의 딥링크 입력 검증 권고 Low

MASVS-PLATFORM · CWE-939 (Improper Authorization of Indexed Resource) · 위치: MainActivity

증거
exported 런처 액티비티가 https 및 커스텀 스킴 딥링크를 처리합니다. 
<data android:scheme="https" android:host="flo-zip.qa.astage.in"/>
<data android:scheme="(custom)"/>
영향
딥링크 파라미터가 검증 없이 WebView 로드·인증 흐름·내부 화면 분기로 전달되면 오픈 리다이렉트·내부 화면 강제 호출 등에 악용될 수 있습니다. (QA 도메인 대상)
권고
딥링크의 호스트/경로/파라미터를 화이트리스트로 검증하고, 외부 URL을 그대로 WebView에 로드하지 마십시오. App Links는 assetlinks.json 검증(autoVerify)을 적용하십시오.

F-5 레거시 READ_EXTERNAL_STORAGE 권한 Info

MASVS-PLATFORM · CWE-250 · 위치: AndroidManifest

관찰
READ_EXTERNAL_STORAGE를 선언합니다. 최신 Android의 Scoped Storage / 미디어 권한(READ_MEDIA_*) 모델 대비 광범위한 레거시 권한입니다. 기능상 꼭 필요한지 검토하고, 불필요하면 미디어 한정 권한으로 대체하십시오. 공격 표면 관점의 경미한 항목입니다.

F-6 네이티브 키 저장은 난독화이며 암호학적 보호가 아님 Info

MASVS-RESILIENCE · 위치: lib/*/libkeys.so

관찰
키 값을 자바/리소스 평문이 아닌 네이티브 libkeys.so에서 제공하는 방식은 평문 노출을 막는 좋은 관행입니다(strings 추출 시 평문 키 미노출, apiKeyValue 심볼만 확인). 다만 네이티브 저장은 난독화일 뿐 결정적 분석가의 동적 추출을 막지 못합니다.
권고
진짜로 민감한 비밀(서버 인증용 시크릿 등)은 클라이언트에 두지 말고 서버 측에 보관하거나 인증 채널로 런타임 수신하십시오. 네이티브 보관은 보조적 방어선으로만 의존하십시오.

06 방법론 및 한계

점검 방식: APK는 서명된 ZIP이므로 압축 해제 후 androguard 4.1.4로 매니페스트·리소스 디코딩 및 DEX 분석을 수행하고, 커스텀 시크릿 스캐너, strings 기반 네이티브/DEX 문자열 추출, 위험 API 교차참조(xref) 분석을 병행했습니다. 기준: OWASP MASVS / MASTG / Mobile Top 10.

한계 1 — 정적 분석 전용: 동적/런타임 테스트(트래픽 가로채기, 후킹, 실기기 실행)는 수행하지 않았습니다. 예컨대 Firebase 키의 실제 악용 가능 여부는 서버 측 설정에 의존하며 별도 확인이 필요합니다.

한계 2 — 난독화: 앱이 R8로 강하게 난독화되어 클래스/메서드명이 단축되어 있습니다. 이 때문에 "앱 코드 대 서드파티 라이브러리" 귀속이 어려워 일부 항목(F-1 등)은 수동 검증 항목으로 분류했습니다.

한계 3 — 도구 환경: 점검 환경의 네트워크 제약으로 jadx/apktool(GitHub 릴리스) 자동 설치가 차단되어, PyPI 기반 androguard로 디컴파일·분석을 수행했습니다. 전체 자바 소스 디컴파일이 필요한 심층 코드 리뷰 시 jadx 결과를 추가 확보하는 것을 권장합니다.

권한 보유 자산에 대해서만 점검을 수행해야 합니다. 본 보고서는 방어적 개선을 위한 것이며, 진단된 약점에 대한 익스플로잇 코드는 포함하지 않습니다.
